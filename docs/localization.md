# Adding a language

The included examples support English (`en`) and Spanish (`es`) in Latin scripts with LuaLaTeX, XeLaTeX, or pdfLaTeX. The included Latin-script starters default to pdfLaTeX for fast previews. Select `--engine lualatex` or `--engine xelatex` when creating documents that need their Unicode or font support. Starter text and metadata are translated, Babel supplies the document language, abstract heading, and `\today` date, and files remain UTF-8.

Locale data lives in `templates/locales/`. Copy one of the existing JSON files to a new language-code filename, keep its keys, and translate the displayed strings. Set `babel` to the supported Babel language name; translate `paper_title`, `notes_title`, `author`, `abstract_text`, and the section heading/text fields. Keep LaTeX commands and citation keys valid: these strings are template fragments, so special characters such as `%`, `&`, `_`, and `#` need their usual LaTeX escaping when used as ordinary text. JSON also requires each literal backslash to be doubled. The creator discovers locale files; the project configuration records the selected code.

Then generate both a paper and notes project with the new code, read the generated source, and compile each using the intended engine. Check headings, the abstract, punctuation, accents or shaping, bibliography localization, dates, and PDF text. Add a small source example under `examples/` and document exactly which engine, language packages, and fonts it requires. If the language requires extra packages, update both `.devcontainer/Dockerfile` and `templates/common/.devcontainer/Dockerfile`, and keep the generated-project README accurate.

To expose a supported locale in the VS Code picker, add its label and code to the language choices in `vscode-extension/create-project.js`. Repackage with `npm run package --prefix vscode-extension`; packaging refreshes the bundled templates from this checkout. The CLI discovers locale files automatically, while the picker lists the languages explicitly covered by the extension.

The templates use Babel, `csquotes`, and `biblatex`; their language support depends on installed packages and language data. LuaLaTeX/XeLaTeX use `fontspec`, while pdfLaTeX uses T1 encoding and UTF-8 input. Latin Modern Roman is sufficient for the included examples. Other scripts may require different fonts, font encodings, or a revised preamble. Install fonts where the engine runs: a font on the host is not automatically available in the container. Prefer fonts with redistribution terms suitable for the project and record their source and version.

Right-to-left languages are an extension point rather than a supported v0.1 example. Choose an engine and language package configuration that supports the script, supply appropriate fonts, and check bidirectional paragraphs, mixed-script citations, punctuation, headings, and PDF copy/paste. A translated locale JSON alone does not establish RTL support. Add a separate preamble/template when the current Babel setup cannot provide the required behavior.

In an existing project, `language:` in `project.yml` is descriptive metadata. Changing it does not rewrite translated text or switch Babel. Update the document's language declaration and content directly, change `engine:` if needed, and record extra dependencies in the project's container definition and README. The helper reads a small flat YAML subset rather than implementing general YAML.
